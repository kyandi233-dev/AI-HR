# 运行指南

本文档统一说明实验环境、通用参数、材料流程与批次管理。研究变量与比较逻辑见[研究设计](研究设计.md)；结果结构及字段含义见[数据与存档](数据与存档.md)。所有示例命令在**项目根目录**执行，默认使用 Windows PowerShell。

## 1. 环境配置

~~~powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
~~~

- **依赖**：见 `requirements.txt`；虚拟环境激活后可用 `python` 代替完整解释器路径。
- **API 密钥**：在项目根目录新建 `.env`，填写 `DEEPSEEK_API_KEY=实际密钥`；若终端已有同名环境变量，则优先使用环境变量。
- **安全**：`.env` 与 `.venv/` 由 Git 忽略，不应提交到仓库。
- **离线测试**：上述 `unittest` 命令不发送真实 API 请求。

## 2. 配置及优先级

| 配置层 | 文件或入口 | 作用 |
|---|---|---|
| 任务实现 | 各模块的 Python 脚本及 `prompts/` | 组装材料、条件和输出格式 |
| 默认模型配置 | 各模块 `config/settings.json` | 模型、温度、thinking、输出上限、超时及并发 |
| 批次计划 | 各模块 `config/*.json` | 任务、运行标识、阶段、重复次数、职业及材料版本 |
| 显式命令参数 | `--run-id`、`--repeat`、`--concurrency` 等 | 覆盖对应批次字段 |

- **批次参数顺序**：显式命令参数优先于批次计划，未指定的字段采用程序默认值。
- **模型参数覆盖**：批次计划中的 `profile_overrides` 可覆盖默认配置的 `model`、`temperature`、`thinking`、`max_tokens`。
- **任务入口**：模块脚本通常限定允许执行的任务类型；跨模块通用命令可通过 `python -m shared.cli` 使用子命令。
- **参数记录**：实际请求、模型配置和完整提示词分别存于批次文件与逐次输入记录，不能仅依靠当前的 `settings.json` 还原历史实验。

## 3. 材料准备与实验顺序

1. **职业资料**：按职业登记下载 O*NET 初始页面，解析为 `structured_en.json`，在职业审核表选择职业；生成阶段直接使用完整结构化资料，不另外制作 `profile.txt`。
2. **岗位描述**：使用 `run_material_generation.py --task jd` 保存完整输入预览并生成 JD；在审核总表“JD是否纳入”列标记 `1` 后，由 `approve_materials.py --run-id <批次号> --task jd` 提取纯岗位公告。具体命令和本轮共同设定见[JD与简历生成](JD与简历生成.md)。
3. **简历与故事**：通过 `run_material_generation.py --task resume` 按已批准或配套 JD 生成分级简历，通过 `run_morality_generation.py` 按道德基础分批生成中性/负面配对故事（见[道德情境编制方案](道德情境编制方案.md)）；完成四人独立审核与最终批准导入。
4. **实验材料快照**：由各实验的 `snapshot_materials.py` 复制选定材料，记录清单及摘要。材料内容修改后创建新版本，不覆盖已有快照。
5. **实验2**：在其材料版本上评价行为属性与岗位直接专业关联性，按结果和研究标准选择材料。
6. **A 条件预评估（可选）**：在实验3材料版本上运行 `baseline`，查看专业能力评分分布与稳定性。当前筛选名单须人工确定，程序不会自动选取简历。
7. **正式招聘评价**：固定正式材料版本，使用新的 `run_id` 执行 `abc`；预筛 A 评分不作为正式 A 结果。

材料生成、人工批准和版本复制的目录约定见[材料准备 README](../material_preparation/README.md)。实验2、3各自的运行入口见其模块 README。

## 4. 常用执行入口

| 操作 | 入口或任务 |
|---|---|
| 职业状态 | `python src/hrpilot.py status` |
| O*NET 来源抓取 | `python material_preparation/fetch_occupations.py --occupation software_developer` |
| JD 与分级简历生成 | `python material_preparation/run_material_generation.py --task jd\|resume ...`（单任务构造：`generate_jd.py`、`generate_resumes.py`） |
| 道德材料生成与审核表 | `python -m material_preparation.run_morality_generation`、`python -m material_preparation.export_morality_review` |
| 批准材料导入 | `python material_preparation/approve_materials.py --run-id <批次号> --task jd\|resume` |
| 简历与故事辅助审读 | `material_preparation/review_resumes.py`、`review_morality.py` |
| 实验1 | `python experiments/exp_1_principles/run.py` |
| 实验2 | `evaluate_morality.py`（`moral-check`）、`evaluate_relevance.py`（`moral-relevance`） |
| 实验3 | `python experiments/exp_3_hiring/run.py --task abc` |
| 单独 A 条件 | `python experiments/exp_3_hiring/run.py --task baseline` |

**预览**：默认只生成计划和完整输入示例，不调用模型、不写实验结果。正式请求须显式添加 `--execute`。

示例：实验1在已准备环境中建立新预实验批次。

~~~powershell
python experiments/exp_1_principles/run.py --run-id principles_pilot_02
python experiments/exp_1_principles/run.py --run-id principles_pilot_02 --execute
~~~

示例：实验3仅运行 A 条件（需预先建立对应材料快照）。

~~~powershell
python experiments/exp_3_hiring/run.py --task baseline --occupation software_developer --materials-version pilot_materials_v1 --run-id hiring_a_pilot01 --repeat 5
python experiments/exp_3_hiring/run.py --task baseline --occupation software_developer --materials-version pilot_materials_v1 --run-id hiring_a_pilot01 --repeat 5 --execute
~~~

示例：按已保存的计划执行 A/B/C。

~~~powershell
python experiments/exp_3_hiring/run.py --batch experiments/exp_3_hiring/config/hiring_example.json
python experiments/exp_3_hiring/run.py --batch experiments/exp_3_hiring/config/hiring_example.json --execute
~~~

使用 `--batch` 时须检查计划内的职业和材料版本是否已有相应文件；示例计划不代表材料已就绪。

## 5. 批次标识与执行控制

| 字段或参数 | 定义 |
|---|---|
| `task` | 实验或材料任务类型 |
| `run_id` | 批次唯一标识与目录名称（材料准备统一采用 `YYYYMMDD_三位累计编号`；仅允许字母、数字、`_`、`-`，且以字母或数字开头） |
| `stage` | `development`、`pilot`、`main`；仅记录数据用途，不改变模型参数 |
| `repeat` | 相同条件或材料组合的独立调用次数 |
| `count`、`start_index` | 材料生成份数与起始编号 |
| `occupations` / `--occupation` | 执行任务的职业范围 |
| `materials_version` | 实验2、3所使用的固定材料快照 |
| `--concurrency` | 最多同时执行的请求数 |
| `--limit` | 本次最多发起多少条待运行请求；不改变计划总量 |
| `--retry-failed` | 在同一批次内重试失败或中断的调用 |

- **新批次**：输入材料、提示词、模型参数或研究条件发生变化时，使用新的 `run_id`。
- **续跑**：相同 `run_id`、输入与参数下，已成功试次跳过；失败项必须显式添加 `--retry-failed`。
- **记录**：每次重试产生新的 `attempt`，历史输入输出不被覆盖。
- **并发**：`sequence` 表示计划顺序；实际运行时间以时间戳为准。并发数不是实验条件，也不代表调用发生顺序。
- **草稿编号**：跨批次重复使用相同简历或故事编号，可能触发同名草稿冲突；新材料应调整起始编号或先整理原草稿，不直接覆盖历史材料。

## 6. 结果检查与导出

~~~powershell
python -m shared.cli export --task principles
python -m shared.cli export --task baseline
python -m shared.cli export --task abc
~~~

- **记录目录**：实验批次包含 `batch.json`、`results.csv` 和 `records/`。材料生成采用总批次→职业／维度→单次调用，每批“批次信息.json＋调用清单.csv”，每次“input.json＋output.json”，见[材料生成记录](材料生成记录.md)。
- **成功条件**：有效响应须通过停止原因、JSON 格式（适用时）、字段范围和必要理由等检查；其余异常保留原始响应。
- **重复分析**：导出的 CSV 每次调用尝试一行，分析正式结果前须筛选 `stage=main`、有效状态，并识别重试记录。
- **材料核对**：启动实验2、3时校验本实验的固定材料快照，不在运行中手工修改材料或结果。
- **失败处理**：检查 `status`、`error_message`、`finish_reason` 和 `validation_warnings`，按需补跑。
- **版本管理**：材料准备记录（`material_preparation/results/`）纳入 Git 同步；实验结果目录（`experiments/*/results/`）默认被 Git 忽略，需提交特定批次时使用 `git add -f <批次目录>`；不得上传 `.env` 等敏感文件。

完整结果结构与字段见[数据与存档](数据与存档.md)。

## 7. 执行前后检查

**执行前**

- 对应职业、批准材料和固定版本已准备。
- `run_id`、`stage`、`repeat`、职业、模型及参数符合计划。
- 预览中的调用数量与完整输入符合研究条件。
- 已明确本批次属于材料生成、筛选、预实验还是正式数据。

**执行后**

- 核对成功、失败、跳过和中断的数量。
- 检查 `results.csv`、异常记录和模型返回标识。
- 保存材料纳入记录及实验变更记录；必要时更新[更新记录](更新记录.md)。
- 正式数据分析前确认预筛数据与正式评价数据未混用。
