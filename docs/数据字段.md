# 输入、输出和分析表

## 每批一个目录，每次输入/输出分别一个JSON

原则：`results/principles/<run-id>/`；道德材料：`results/morality/<task>/<run-id>/`；职业任务：`results/<occupation>/<phase>/<run-id>/`。

- `batch.json`：task、run_id、stage、职业选择、模型参数、接口、全部试次与输入摘要、计划顺序、执行协议摘要。冻结输入而非整个工程，CSV模块变化不影响续跑。
- `<task_id>_a01.input.json`：run_id、task_id、attempt、sequence、时间、条件及重复编号；request 中含完整 messages、config 和接口地址。
- `<task_id>_a01.output.json`：原始 raw_response、逐字 answer、校验后的 parsed、status、错误、实际模型、用量、完成原因、程序版本摘要。网络未返回时 raw_response 为 null。输入已写但没有最终输出视为中断，不自动重发。
- `results.csv`：本批每次尝试一行，答案展开为列。100次成功且无重试就是100行，两个问题都在同一行。

`stage` 区分 development/pilot/main；迁移时无法确定则标记 unknown，不能擅自视为正式数据。run-id 用研究者指定日期和阶段命名，如 `20261117_principles_main_01`；精确运行时间统一存 UTC。唯一键为 task、occupation（如适用）、run_id、task_id、attempt。

成功记录续跑跳过，失败/中断需要显式 --retry-failed；新尝试用 a02，不覆盖旧文件。分析时筛选 status=ok，同时报告失败和重试数量。原始失败回答不能作为合法分数。

## CSV保留字段

- 身份与条件：run_id、stage、task、task_id、attempt、sequence、occupation、condition、repeat、resume_id、pair_id、background_type，按任务适用；不适用留空。
- 模型与运行：requested_model、returned_model、temperature、thinking、max_tokens、timestamp_utc、status、finish_reason、prompt_tokens、completion_tokens、total_tokens、error_message。
- 原则题目：task1_priority、task1_weight_ability、task1_weight_morality、task1_importance_ability、task1_importance_morality、task1_reason；task2同样六列。权重合计100，重要性1–7。两题来自同一条回复，保留配对关系。
- 招聘：education_fit、work_experience、professional_skills、accomplishments、overall_suitability（1–5）、interview_probability（0–100）、reason。
- 材料检验：按任务展开 moral_valence、moral_foundations、comprehensibility、naturalness、direct_professional_relevance 等。

哈希、接口ID、system_fingerprint、SDK版本和缓存细节留在 JSON 中，不铺满常用分析CSV。完整数据从来不只依赖 CSV。

## 历史记录转换

`python src/hrpilot.py migrate-results` 不调用模型。逐条转换已保存的请求、原始响应、答案及失败尝试，读取校验后将原文件留在该批次 legacy/，同时记录原文件 SHA256。保留原时间、模型、程序摘要和分值，不把整理时间当作实验时间。已有转换目标内容冲突时停止，不覆盖。历史批次继续保留原始材料；新实验用新run-id。
