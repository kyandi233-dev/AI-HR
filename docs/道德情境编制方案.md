# 道德情境编制方案

本轮交付定义、编制标准、固定输入、生成prompt、脚本与审核表结构；**暂不调用生成模型**。具体情境由统一流程批量起草后筛选，不以手工选出的少量例子代替材料池。

## 理论定义与原作者编制标准

采用道德基础理论（Moral Foundations Theory，MFT）组织内容，以道德基础情境材料（Moral Foundations Vignettes，MFV）为主要改编来源。定义主要依据 Graham 等（2013）第2.4节和表2.1；下表操作化依据 Clifford 等（2015）材料开发部分（约1180–1182页）；自由主题另参考 Iyer 等（2012）。

| 主题 | 概念定义 | MFV作者的操作化与编写边界 |
|---|---|---|
| 关怀／伤害 | 对痛苦、脆弱及照料需要的关切，涉及避免情感和身体伤害 | 分人的情感伤害、人的身体伤害、非人动物的身体伤害。尽量回避等级关系，优先陌生人，减少权威、自由与忠诚混淆。 |
| 公平／欺骗 | 对合作互惠、作弊、搭便车及不公获利的关切 | 聚焦作弊与搭便车；回避紧密群体、违抗上级，以及种族、性别和结构性不平等议题。 |
| 忠诚／背叛 | 对群体成员义务、团结及内外群体关系的关切 | 采用较窄范围：公开发生并威胁本群体声誉；存在竞争性外群体；行为者是可识别的成员或代言人。避免明显伤害。 |
| 权威／颠覆 | 对正当权威、等级关系与传统的尊重 | 对父母、教师等传统权威人物或权威机构、象征的不服从与不尊重。迁移到成人私人生活时需保留可识别的权威关系。 |
| 神圣／堕落 | 对身体或精神污染、贬损及纯洁的关切 | 原MFV均含生理厌恶元素，涉及性相关、贬损与污染；未采用神圣器物亵渎，以减少其他基础混淆。 |
| 自由／压迫 | 对支配、胁迫及自主选择受限的关切 | 描写胁迫或剥夺选择，突出掌权者施压，包括父母、伴侣、雇主等关系。普通建议与协商不等同于压迫。 |

作者的共同原则：测量第三方对具体行为的判断；先起草大量事件，尽可能改编已有刺激；同类内部保持内容多样；采用可能发生的日常事件，回避明显政治内容、特定群体及特殊文化知识；尽量减少其他基础混入。原版以“You see”引入，以短英文句控制长度与可读性，服务于行为及神经影像任务；英文长度标准不直接用于中文摘要。

原研究1采用目标基础归类至少60%、任一特定非目标基础低于20%的筛选标准。这是原条目的人类单选任务标准。原MFV另有“不寻常但非道德错误”的社会规范对照，**没有逐条提供自然中性配对**。

## 本研究的操作化、来源与写作规则

私人道德信息指候选人在工作之外的一件具体行为，以第三人称背景调查摘要呈现。每件事件形成负面、中性两个版本，在相同岗位与简历下比较其影响。六类用于组织内容，不预设模型具有相应的人类心理机制。

来源固定保存在 `material_preparation/sources/morality/mfv_catalog.json`：完整保留132条原记录、英文、现有中文译文、归类比例、错误程度和推荐状态。116条道德情境各设2种改写任务；推荐与未推荐条目均保留供尝试。16条非道德社会规范对照只作参考，不直接充当配对中性版本。六类各加6个依定义与编写规则新编的任务，默认共268项；这是生成计划，不是已生成或已验证材料数量，可通过配置调整。

两种改写方向分别强调保留原关系结构，以及迁移到另一具体私人活动。项目编号不冒称原作者编号；新编事件不冒称MFV条目。无法成人化、私人化或自然配对的条目可返回 `not_adaptable` 和原因，不强行凑齐。

- **每次输入有依据**：包含主题定义、作者规则、项目规则和具体原条目；新编任务则指定概念范围和活动方向。
- **中性行为与事件相关**：保留同一活动、关系和记录理由，呈现普通参与或常规处理。不随意添加行程、餐点或无关动作凑字数，也不只写“没做坏事”。
- **保持普通中性**：不改成主动助人、牺牲或道德表态。若共同场景已含伤害、救助义务或强烈禁忌，不能把失责当作中性；应重构场景或报告不适配。
- **叙述自然且可比**：第三人称，一件具体事件；两版视角、来源确定程度、事件数量、篇幅和细节量接近。每版建议50–100中文字、1–3句，是项目起草约定。
- **控制额外信息**：不写人格标签、旁人谴责、处分、招聘结论或直接专业能力证据；保留理解行为所必需的关系、规则与意图。
- **内容多样，写后筛选**：不靠换词或换人名充当新情境；检查主题、效价、理解性、自然性、配对合理性和专业关联。原推荐状态不转移为改编效度，不按招聘效应挑材料。

特别区分忠诚与一般群体偏好、权威与不正当控制、纯洁与单纯卫生健康。完整机器可读定义和规则保存在 `config/morality_protocol.json`。

## Prompt、脚本与运行方法

下列路径均相对于 `material_preparation/`。

| 文件 | 用途 |
|---|---|
| `config/morality_generation.json` | 来源、改写数量、新编数量、批次和审核员 |
| `config/morality_protocol.json` | 六类定义、作者操作化、共同原则与项目规则 |
| `prompts/morality_pool.txt` | 固定生成prompt，逐条注入依据及具体来源 |
| `morality_inputs.py` | 确定性构造编号与完整输入，校验输出身份和结构 |
| `run_morality_generation.py` | 保存全量请求预览；显式执行时调用模型，保留原响应和草稿 |
| `export_morality_review.py`、同名`.mjs` | 创建总表和独立审核表，按编号与版本保留人工意见 |

在项目根目录运行：

```powershell
# 保存全量prompt和请求预览，不调用模型
.\.venv\Scripts\python.exe -m material_preparation.run_morality_generation

# 创建或刷新汇总表和个人审核表，不调用模型
.\.venv\Scripts\python.exe -m material_preparation.export_morality_review
```

后续授权生成时，在第一条命令后加 `--execute`。用 `--foundation care`、`--source-id mfv_003` 或 `--limit 10` 分批运行；`--concurrency` 控制并发，`--retry-failed` 明确重试失败项。更改来源、prompt或参数须换 `--run-id`；相同编号已有草稿时先归档，脚本阻止覆盖。

请求保存完整prompt、输入文件摘要、模型参数、原响应、解析结果与状态。`not_adaptable`保留原因，不产生伪正文；失败或未完成调用与未调用任务分别标记。固定输入与档案支持复核过程，随机生成不保证逐字重现。旧 `generate_morality.py` 是按主题自由起草的兼容入口，本方案使用上述新入口。

## 汇总与独立审查资料

文件位于 `material_preparation/review/mority/`，沿用项目已有目录拼写。

- `道德材料汇总.xlsx`：状态、来源、完整prompt和正文链接、生成备注、三人意见及最终纳入决定；另含132条原条目和定义标准。
- `审核员A.xlsx`、`审核员B.xlsx`、`审核员C.xlsx`：各自独立填写理解性、自然性、两版效价、主要主题、配对合理性、明显专业证据、结论与问题说明；各附定义标准。

本轮268项均为“待生成”，正文及人工评分留空。生成后刷新即出现配对正文链接；再次刷新汇入各人的意见，不自动决定最终纳入。人工内容检查与后续结合JD的专业关联性测量分开。原职业、简历总表与其审核记录不受此流程改写。
